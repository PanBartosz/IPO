Admin help & workflow

Back to dashboard

Use this guide when running an IPO edition. It explains what each tab does, how to move through the competition stages, and what to watch for if you are new to the system.

Quick glossary

  • Batch — a Stage 1 reading plan. Only one batch can be published at a time.
  • Group — a reading team (typically 4 teachers) handling a set of essays.
  • Finalized essay — a student upload locked by the student; cannot be replaced without admin help.
  • Finalized score — a teacher-submitted score locked for the portal until an admin clicks Unlock on the scoring page.
  • Extra reader — an additional evaluator assigned when Stage 1 scores are far apart.
  • Admin override — a score saved by staff (status tags show “Admin entered” or “Admin override”).
  • Grading lock — an admin toggle that pauses score editing for a single student or an entire stage until reopened.

1. Before registrations open

  1. Create admin accounts via ADMIN_USERS or database insert so organizers can sign in.
  2. Review Settings: deadlines, SLA hours, packet print mode, SendGrid credentials.
  3. Confirm upload directory (Settings → Uploads) and that disk space is available.
  4. Share registration links (top navigation) with delegations.
  5. Optional: load mock data in a staging copy using python scripts/seed_mock_data.py --reset.

2. Registration period

  1. Watch the Students and Teachers tabs for new entries; edit records if delegations request corrections.
  2. If automated emails are enabled, confirm SendGrid shows deliveries (spot check participants if unsure).
  3. Use Messages to email broad instructions (e.g., upload deadlines) to all teachers.
  4. The Dashboard should show rising counts in the Students/Teachers cards; alerts will flag “students without uploads” once deadlines approach.

3. Essay upload window

  1. Students log in under “Essay upload” and submit PDFs. They can preview the exact stored copy and must click Mark essay as finished when satisfied.
  2. The Uploads table shows status tags:
    • Pending — no upload yet.
    • Uploaded — a file exists but is editable.
    • Finished — student locked the essay.
  3. Remind students near the deadline using Messages; the Dashboard alerts list will include “students without uploads”.

4. Stage 1 planning

  1. Open the Planner tab. Create or load the Stage 1 batch, add groups, and assign teachers. Red warnings mark groups with fewer than four active readers.
  2. Use “Auto-generate groups” or “Auto-assign essays” to quickly populate from available teachers/essays; review manually afterwards.
  3. When satisfied, click Publish. Only one batch may be published at a time; publishing copies the plan to teachers.
  4. Generate reader packets (PDF). If Settings → packet print mode is set to “double sided”, the export inserts blank pages so each title sheet starts on the front of a paper and every essay begins on a new page.
  5. Notify teachers via Messages that packets are available. Quick “Message” buttons appear next to teacher names throughout the app.

5. Stage 1 scoring

  1. From Uploads, choose a student and click “Scores”. Enter or edit each reader’s score. If the spread exceeds 3 points, the app recommends an extra reader; assign one via the same page.
  2. Status tags highlight progress: Draft saved, Teacher finalized, Admin entered, Admin override, or Locked by admin. Click Unlock next to a reader to reopen a finalized score.
  3. The “Lock assignment grading” button pauses edits for that student; the Dashboard provides global Stage 1/Stage 2 locks when you need a freeze across the board.
  4. When all required scores are present, use “Mark Stage 2 qualified” to flag the essay (automatically clears the “Needs extra” tag if average ≥ 7). The save button only logs updates when a score actually changes.
  5. The Dashboard Stage 1 card updates automatically (completed vs expected scores, pending count, completion percentage).

6. Stage 2 and beyond

  1. Use the Stage 2 tab to view promoted essays, average scores, spreads, and Stage 3 recommendations.
  2. Assign Stage 2 readers and generate Stage 2 packets; workflow mirrors Stage 1. The actions column again offers Unlock to reopen finalized teacher scores and “Lock assignment grading” to pause edits.
  3. Post logistics updates (ceremony times, translation sessions) via Messages.
  4. After scoring closes, visit Exports to download the SQL dump and essay ZIP (optionally only finalized essays). Store these securely.

Dashboard details

The dashboard provides live status:

  • Students card — total registered, uploads pending/complete, absent count.
  • Teachers card — active teachers, teachers still missing scores, absent count.
  • Stage 1 card — completed vs. total assignments, pending essays, entered vs. expected scores, completion percentage.
  • Stage 2 card — assignments completed, candidate count, pending, completion percentage, spread for Stage 2 scores.
  • Both Stage cards include quick buttons to lock/unlock grading portal-wide for that stage.
  • Alerts panel — auto-generated reminders such as “students without uploads”, “teachers pending scores”, “understaffed groups”, “Stage 2 essays awaiting readers”. Click an alert to jump to the relevant tab.
  • Deadlines & SLA — displays configured deadlines and SLA windows with time-remaining (overdue items marked warning).
  • Teacher workload — top teachers with high pending/assigned counts; use to rebalance groups.
  • Students without uploads — latest registrations missing essays (top 10).
  • Stage 1 essays needing scores — essays with incomplete reader submissions (top 8).

Tab reference

  • Planner — manage Stage 1 batches, groups, assignments, packets. Tools for auto-generation and understaffed warnings.
  • Students & Teachers — browse/edit records; quick “Message” buttons next to teachers.
  • Uploads — monitor essay status, download PDFs, jump to scoring.
  • Stage 2 — monitor promotion candidates, assign Stage 2 readers, generate packets.
  • Messages — compose announcements (with optional email), load templates, archive/restore, view teacher board.
  • Logs — searchable audit trail for registrations, packets, messages, exports.
  • Exports — download SQL dump (MySQL/MariaDB via mysqldump or SQLite copy) and essay ZIP with manifest; activity logged.
  • Settings — configure deadlines, SLA, duplex printing, email automation/templates.
  • Help — this page.

Roles & contingency tips

  • Head organizer — keeps Settings current, monitors Dashboard alerts, approves packet publication.
  • Registration desk — watches Students/Teachers tabs, corrects data, checks for missing essays.
  • Scoring supervisor — enters reader scores, schedules extra readers, promotes Stage 2 candidates.
  • Communications lead — posts Messages, confirms SendGrid deliveries, coordinates teacher acknowledgments.
  • If SendGrid fails — disable automatic emails in Settings, resend instructions manually; Logs confirm what was attempted.
  • If duplex printing misaligns — verify packet print mode is set appropriately; regenerate packets after changing the setting.
  • After exports — move downloaded SQL/ZIP to encrypted storage; consider deleting temporary backup files from the server.

Additional reminders

  • Automated emails only send when both SENDGRID_API_KEY and SENDGRID_FROM_EMAIL are set and the toggle is enabled.
  • Students preview the server-stored PDF, so once marked finished the file exactly matches what teachers receive.
  • Packet duplex mode inserts blank pages where needed so duplex printers start each title page and essay on the front side.
  • Exports and Messages create audit log entries — consult Logs whenever you need to trace actions.
  • Teacher portal disabled? Locks and unlocks still update internal state; they take effect the moment you re-enable the portal.
  • Refer to share/International Philosophy Olympiad Statute.html for official rules and procedures.
